What runs in parallel: Read-only checks

Parallel-safe (Read-only context)

  • Request & acknowledgement shape validation
  • Resource binding checks
  • Writer & replica Ed25519 signatures
  • Request content & event hashes
  • Proposed-hash equality
  • Request/acknowledgement binding
  • Freshness & duplicate conflicts
  • Distinct-replica quorum verification
The context contains cloned identifiers, quorum policy, and pinned public-key registries. It is strictly read-only.

Never parallelized (Lock-held state)

  • Ownership records & epochs
  • CAS state & generations
  • Nonce ledgers & idempotence
  • Durable snapshots
  • OS-backed locks
The verifier cannot mutate state. Phase 43 lock-held revalidation remains the sole authority for state transitions.
