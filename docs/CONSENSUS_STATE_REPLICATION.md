# Consensus and State Replication

## Design boundary

`src/consensus.rs` implements a bounded, transport-agnostic state machine. It does not open sockets, spawn election timers, or grant network/tool authority. A caller may carry its typed messages over an approved transport while the core enforces membership, term, log, quorum, and state-machine invariants.

## Core behavior

| Concern | Contract |
|---|---|
| Membership | Node IDs are bounded and control-character-free; every sender and candidate must belong to the configured cluster. |
| Election | A candidate increments its term, votes for itself, and becomes leader only after a quorum of valid votes. Higher terms force follower state. |
| Proposal | Only a leader may append a typed `Set` or `Delete` command. Keys, values, member count, batch size, and log length are bounded. |
| Integrity | Every log entry carries a SHA-256 digest of canonical serialized command content. Hash or index mismatches fail closed. |
| Commit | A leader applies only current-term entries acknowledged by a quorum. A local append alone does not commit state. |
| Replication | `AppendEntries` validates previous index/term, rejects stale terms, truncates conflicting suffixes, appends bounded entries, and advances followers only to the leader's commit index. |
| Snapshot | Replicated state snapshots include term, commit index, last-applied index, state, and a deterministic state hash for equality checks. |
| Membership change | `ConfigurationJoint` carries old and new sets, requires a double majority, blocks concurrent changes, and precedes `ConfigurationFinal`. |
| Dynamic re-voting | Elections and commit acknowledgements use the active set; joint mode requires a majority in both old and new sets. |
| Crash recovery | Snapshot staging can be explicitly recovered after a process abort before rename; invalid installs leave node state unchanged. |
| Authenticated benchmark | Deterministic Ed25519 envelope benchmark reports verified/dropped messages, p95 verification time, throughput, and quorum availability under partitions. |
| Socket transport | Length-prefixed TCP frames are bounded before allocation and carry typed authenticated envelopes. |
| Cluster/replay binding | Envelopes bind cluster ID and sender ID; receivers use trusted keys and insertion-ordered bounded replay windows. |
| Power-loss recovery | A process-abort fixture leaves a partial staging file, then explicit recovery removes it before atomic rewrite. |
| Timer and failure detection | Injected-tick `ElectionTimerAction` plans provide bounded elections, leader heartbeats, deterministic jitter, peer suspicion, and clock-safe fail-closed behavior without background threads. |
| Replication flow control | `ReplicationFlowAction` provides bounded `Send`, `Backpressured`, or `Idle` work with one in-flight batch per follower, exact retry boundaries, and independent peer windows. |
| Remote audit ordering | Signed remote-audit envelopes bind source stream/sequence and record hashes; durable outbox replay is deterministic, idempotent, and retains gaps or retryable acknowledgements. |
| Log compaction | Committed/applied prefixes are discarded only within bounded retention and discard limits; logical indexes retain a boundary term and followers behind it require a configuration-bound snapshot. |
| Durable compaction recovery | Snapshot and manifest staging is validated, fsynced, atomically promoted, and recovered deterministically; malformed or partial staging is aborted without replacing the prior durable pair. |
| Snapshot install readiness | Per-follower snapshot transfers use exact hash/frontier acknowledgements; validated and durably staged states do not advance progress, and only installed snapshots advance replication. |
| Snapshot transfer metrics | Per-follower byte counters are bounded by the exact serialized snapshot frontier; rolling bandwidth windows return exact retry ticks and do not share quota state across followers. |
| Snapshot cancellation | Explicit cancellation clears active transfer authority, records a bounded retry deadline and cancellation metric, and leaves transport/storage/scheduling ownership outside the consensus core. |
| Durable term/vote state | `DurableConsensusState` binds node identity, current term, voted-for identity, replay epoch, replay term floor, and a canonical state hash; atomic storage rejects malformed, partial, mismatched, or rollback state. |
| Epoch-bound replay | Authenticated envelopes sign the replay epoch; replay windows reject stale epochs and terms, bound nonce memory, and clear state only through monotonic epoch rotation. |
| Cross-node compaction coordination | Leaders produce a hash-bound plan with per-follower lag, stable/joint remote-quorum admission, explicit waiting, and compaction only after readiness. |
| Follower snapshot requests | Followers emit typed, identity/term/reason/frontier-bound requests when append predecessors or incremental bases fall inside compacted history; leaders validate and delegate to bounded snapshot transfer. |
| Socket backpressure | Authenticated transport admits serialized bytes against isolated per-peer send quotas and receive windows, returns exact retry ticks, releases send bytes, and resets quota state on epoch rotation. |
| Durable socket queues | Queue frames carry SHA-256 digests, FIFO sequences, peer/epoch bindings, and bounded bytes; atomic persistence restores queue and quota state across restart and rejects partial, tampered, mismatched, or non-FIFO state. |
| Authenticated durable delivery | Queued payloads are re-verified before send, one delivery is active per peer, injected socket crashes retain the queue, and acknowledgement occurs only after flush. |
| Replicated delivery acknowledgement | A flushed frame remains in the FIFO queue until authenticated, owner/term/epoch/frame-bound acknowledgements reach the configured quorum; same-sender duplicates are idempotent and conflicting hashes fail closed. |
| Cross-host queue ownership | Durable snapshots persist hash-bound owner leases and acknowledgement evidence; a new owner imports only source-bound state and accepts higher-term/higher-epoch transfers, clearing stale delivery authority. |
| Partition-aware ownership fencing | Bounded quorum-loss observations and finite lease expiry produce a durable `OwnershipFenced` action before socket write; fences survive restart and clear only through a validated higher-term/higher-epoch transfer. |
| Authenticated remote fence observations | A trusted peer can sign a quorum-loss fence bound to the active owner term, epoch, quorum, and queue; same-hash reports are idempotent and same-tick conflicts fail closed before durable mutation. |
| Deterministic multi-region failover | A seeded simulator models regions, directed drop/delay/duplicate/reorder/corrupt links, observer quorum, durable snapshots, clock-skew fencing, higher-term transfer, replayable traces, and safety/liveness outcomes without claiming cloud or kernel behavior. |
| Secure deterministic replay | Signed replay manifests bind canonical fault schedules to scenario, cluster, signer, replay epoch, term, seed, nonce, bounds, and public key; cloned application plus event trace seals prevents partial mutation and accepts only verified traces. |
| Multi-region disaster recovery | Signed distinct-observer failure observations bind active region, owner term, ownership epoch, tick, and snapshot digest; observer quorum gates promotion, higher term/epoch prevents stale takeover, and commit fences the previous region while preserving one active region. |
| Durable recovery authority | `DisasterRecoverySnapshot` binds controller state, observer keys, membership epoch, evidence, proposal identity, event trace, and a canonical SHA-256 hash; `DisasterRecoverySnapshotStore` performs bounded staging, sync, atomic rename, cleanup, and validate-before-restore. |
| Observer-membership epochs | Signed failure observations bind the current observer registry epoch; strictly higher rotation validates public keys, clears stale evidence and pending authority, and rejects rotation during prepared or committed recovery. |
| Concurrent partition-race arbitration | Deterministic simulator branches can diverge under asymmetric faults, but one recovery controller arbiter admits one exact pending proposal, commits one candidate, and preserves the single-active-region invariant. |

## Production boundary

This slice is intentionally not a complete production consensus deployment. It still requires operator-approved compaction scheduling, storage quotas and backup retention, cross-device rename handling, encryption-at-rest policy, membership configuration backup/restore, mTLS or mesh confidentiality and peer authentication around the TCP frame layer, durable replay-state replication across restart and membership change, socket-thread queue ownership, cross-process per-peer quota replication, transport-level backpressure and bandwidth quotas, authenticated durable queue delivery ownership, replicated queue authority across hosts, real replica transport and quorum scheduling, authenticated failure-detector consensus and observer membership policy, lease renewal and clock uncertainty handling, split-brain fencing, crash-injection against real process/socket boundaries, durable remote sink quorum and order-token allocation, durable retry execution, metrics export, real scheduler jitter, authenticated snapshot transfer, durable remote install acknowledgements, persistent transfer metrics, durable cancellation intent across process restart, key rotation coordination with replay-epoch rotation, authenticated cross-node compaction coordination, durable snapshot-request intent and deduplication, cross-host quorum validation, deterministic simulation correlation against staging, cloud-region partition testing, load-balancer/DNS convergence, managed-storage replication, process fencing, production replay-key custody and registry distribution, authenticated replay transport, cloud failure-detector authority, durable cross-region snapshot storage, routing convergence, automated promotion rollback, and cross-machine partition, failure-detector, compaction, snapshot-install, replay, and remote-sink testing before production promotion.
 The local partition benchmark measures in-process Ed25519 verification and drop filtering, not network latency or kernel behavior. Runtime policy and consent manifests remain authoritative for all tools, MCP methods, network access, and secrets; cluster membership does not grant any of those capabilities.
